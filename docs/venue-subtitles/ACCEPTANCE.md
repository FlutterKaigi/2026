## 必須ゲート

- [ ] 理事・運営・会場・制作・収録担当が正面スクリーンへの合成を承認した
- [ ] 「登壇者PC映像を1ピクセルも改変しない」方針の例外・解釈と、過去のスポンサーロゴ合成との整合性を理事会等の決定記録へ残した
- [ ] 合成PCに依存しない物理HDMIバイパスを実機で10回連続切替できた
- [ ] 会場機材で実際の入力・投影解像度を確定した（1920×1080は候補値）
- [ ] 実プロジェクターを最後列から確認し、通常視力を前提とした可読性基準を運営が承認した
- [ ] 1行／2行、明るい／暗いスライド、日本語／英語／混在文を確認した
- [ ] 最長fixtureで末尾省略・文字切れ・意図しない改行がなく、生成側のチャンク分割契約を満たした
- [ ] 字幕がスライドのページ番号、コード、注釈、QRコード等の重要領域を隠さず、安全領域を登壇者テンプレートへ反映した
- [ ] 文字サイズ、行高、行数、下余白、背景、色を制作物チームが承認し、本番値として固定した
- [ ] WebSocket切断、翻訳API停止、OBS再起動時にエラー文や古い字幕が観客画面へ残らない
- [ ] 90分の連続fixture再生でcrash・固着・順序逆転がない
- [ ] 発話から確定字幕までの許容遅延と、重大誤訳の判定基準を満たした
- [ ] 実際のPA音声→STT→翻訳→relay→画面のE2E試験を行い、用語集・API障害・credential運用を含むproducer手順を確定した
- [ ] 収録方式をclean／captioned／both／post-productionから選び、信号経路と容量を実機確認した
- [ ] 選択した収録経路で`CAPTION OFF`および物理バイパスへ切り替えても、必要な映像・音声の収録が途切れないことを実機確認した
- [ ] YouTube字幕ポリシーを収録方式と別に決定し、焼き込み字幕との重複可否を確認した
- [ ] relayがループバック以外へのbindを拒否し、書込tokenがURL・OBS設定・ログへ残らないことを確認した
- [ ] 開発者以外の予備担当者がRunbookだけで起動、clear、バイパスを実行できた

## 独立フォールバックゲート

- [ ] アプリチームが正面スクリーン方式と独立して来場者アプリ内字幕を提供できる
- [ ] 合成PC、OBS、caption relayを停止した状態でアプリ字幕のE2E試験に成功した
- [ ] 本番相当の端末・回線・想定同時接続数で可用性を確認した
- [ ] 来場者への利用案内、QR／導線、問い合わせ手順を準備した
- [ ] 正面スクリーンNo-Go決定直後からアプリ字幕へ切り替える責任者と連絡経路を決めた
- [ ] 本番中の`CAPTION OFF`／物理バイパス時に、来場者をアプリ字幕へ誘導する場内案内と担当者を決めた

アプリ字幕はこのブランチの実装範囲外ですが、上記準備を必須とします。正面スクリーン方式の完成度にかかわらず並行開発を止めません。正面表示とアプリ字幕の両方が期限までに未達の場合は翻訳字幕施策全体をNo-Goとし、提供を告知しません。
