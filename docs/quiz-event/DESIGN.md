# クイズ大会の設計

当日の操作・障害時の対応は [RUNBOOK.md](RUNBOOK.md) を参照。

## 参加とチーム

- 受付はダッシュボードで発行した6桁コードの入力。QR・Lumaとの連携は行わない。
- 匿名認証以外のサインインを要求する。コード所持を参加条件とし、チケットの本人確認は行わない。
- 定員は3〜80人。受付準備後は定員を変更できない。4人を基本に3〜5人へ分割し、最大20テーブルとする。
- 同じアカウントは前半・後半を通じて1大会のみ参加できる。同一プロジェクトの既存参加記録も確認する。
- 初出題前の参加取消では参加権を戻す。初出題後の参加者追加・取消・再編成は許可しない。
- 登録済みの遅刻者は割り当て済みテーブルへ合流できる。
- 各チームで1回答を共有する。誰でも変更でき、期限までにサーバーが最後に受理した値を採用する。
- 1問10点。同率順位はすべて表示し、入賞3チームへの絞り込みは会場でじゃんけん等を行う。

## 状態と進行

大会は `draft → published → registration → entryClosed → inProgress → finished`。
受付終了後、初出題前に限り受付再開できる。再開・参加取消はチーム割り当てを解除するため、再編成が必要。
通常の編成ボタンの再実行では既存チームを保持し、明示的な再編成だけが組み直す。

問題は `draft → reading → open → closed → revealed`。
「問題を表示」で読み上げを開始し、「回答開始」を押した時点から制限時間を数える。
期限を過ぎた回答はサーバーが拒否する。運営は締切・正解発表を行ってから次問に進む。
1問以上の正解発表が終わり、出題中の問題がなければ大会を終了できる。
時間超過時は未出題の問題を除外して終了し、出題済みの問題だけで得点・賞を集計する。

正解発表前なら30秒延長でき、締切済みでも回答を再開する。既存の回答は保持する。
すべての運営操作に操作IDを付け、通信エラー後の再試行で同じ操作を重複実行しない。
別の担当者が延長・受付再開した後の、古い締切操作の再試行も状態を巻き戻さない。
読み上げ・回答開始・採点・終了なども再実行で回答や点数が失われないよう状態を検証する。

○×と4択に対応する。問題ごとに制限時間を設定できる。
8問×回答3分＋読み上げ各1分では32分となり、説明・移動・表彰を含まない。
30分枠の場合は当日までに問題数・制限時間と進行を調整する。管理画面に所要時間の目安を表示する。

## サーバーの役割

Cloud Functions（`asia-northeast1`）が受付・進行・回答・採点を担当する。
本番ではApp Checkを要求し、運営操作には確認済み `@flutterkaigi.jp` アカウントと `admins/{uid}` を要求する。
参加者のUIDやメールはクライアント申告値を使わず、認証情報から決定する。

| Callable | 入力・役割 |
| --- | --- |
| `registerQuizParticipant` | `eventId, displayName, entryCode`。コード、定員、重複参加を検証して登録 |
| `submitQuizAnswer` | `eventId, questionId, teamId, selectedOptionIndex`。所属・問題状態・サーバー期限を検証 |
| `quizEventOperation` | `eventId, operation` と操作別引数。公開、受付、編成、出題、採点、終了 |
| `getQuizServerTime` | `serverNowMs` を返し、端末時計の補正に使用 |

受付は定員分の予約枠をトランザクションで取得し、定員超過を防ぐ。
登録ごとの共通カウンタ更新を避け、一斉登録時の競合を抑える。大会状態は同じトランザクションで読み、受付終了との競合も検証する。
運営操作は大会ドキュメントを共通のトランザクション対象にし、二重編成・並行採点時の点数欠落を防ぐ。
回答は大会・問題・チームを同じトランザクションで検証する。
大会終了時の得点は回答と正解から再計算し、集計済み得点への加算だけに依存しない。

6桁コードはサーバーで発行し、再発行すると旧コードを無効化する。
旧実装の `entryClaims` は登録判定に使わない。
不正コードはアカウントごとに1分間5回までとし、定員超過とは区別して表示する。

参加者・回答・チーム・進行状態への直接書き込みは、管理者を含めFirestore Rulesで禁止する。
管理者が直接保存できるのは初出題前の設定・下書き問題とチーム名候補などに限定する。
設定保存は対象フィールドのみ更新する。問題保存・削除は最新状態をトランザクションで確認する。
問題編集画面は非公開の正解・解説を読み終えてから編集可能にし、古い画面から進行を巻き戻さない。

## 表示と通信

回答はCallableで送信し、オフライン書き込みキューには積まない。
参加者画面では「送信中」「受理済み」「受理を確認できない」を区別する。
Firestoreのキャッシュ表示だけでは受理済みとしない。

アプリと管理画面はサーバー時刻に同期し、以後は単調増加時計で残り時間を計算する。
定期同期とアプリ復帰時の同期を行い、古い同期値は使用しない。
画面の秒数にかかわらず、回答可否の最終判断はサーバー時刻で行う。

投影用URLは `/quiz/:eventId/project`。管理画面の操作ボタンや受付コードを表示せず、
現在の問題・選択肢・残り時間・公開された正解・順位を表示する。
投影画面を別ウィンドウに開き、プロジェクターにはそのウィンドウだけを映す。

## 保存先

```text
quizEvents/{eventId}                 設定・状態・revision・admissionSlotsReady
  secret/entry                      非公開の受付コード
  participants/{uid}                表示名・チーム割り当て
  admissionSlots/{slot}              サーバー専用の定員予約（0〜定員−1）
  participantAccounts/{uid}         非公開の受付時アカウント情報
  entryAttempts/{uid}               サーバー専用の不正コード試行
  operations/{operationId}          サーバー専用の運営操作結果
  teams/{teamId}                    メンバー・得点・順位
  questions/{questionId}            問題・状態・サーバー期限
    secret/answer                   非公開の正解・解説
  answers/{questionId}_{teamId}      チームの最終回答
quizParticipation/{uid}             サーバー専用の大会をまたぐ参加記録
```

Authアカウント削除時はクイズの非公開アカウント情報・旧claims・失敗試行も削除する。
試合を壊さないようチーム・回答・表示名・参加記録は保持する。
削除処理は、登録トランザクションも使用する共通の参加記録へ `accountDeleted` を先に保存する。
同じドキュメントへの書き込み競合とマーカーの検証により、実行中の登録が非公開アカウント情報を再作成しない。

スキーマは `packages/data/firebase/schemas/firestore/quiz_*.schema.json`。
クイズ大会データはSTGから本番へのマスター同期の対象には含めない。

## 検証

Functionsの単体・エミュレーターテストで認可、並行登録、定員、重複参加、コード再発行、
編成、状態遷移、サーバー期限、採点、操作再試行とFirestore Rulesを検証する。
Dartの回帰テストで編集競合、秘密情報の復元、Callable引数、時計、回答表示、同率順位、投影画面を検証する。
本番のApp Check、会場Wi-Fi、実機80台、端末復帰を含む進行リハーサルは別途必要。
