# だしゅまると、会場さんぽ

会場マップの **3D** を選ぶと、マップ領域内でだしゅまるを操作できます。下部のアプリナビゲーション、2D/3D切り替え、場所の検索を維持します。専用ページへの遷移はありません。

Flutter **3.47.3 / Dart 3.13.3**、Flutter Scene **0.23.0**を使用します。選定理由は [調査レポート](flutter-scene-research.md)、モデルの出典は [モデルのREADME](../../assets/models/README.md) を参照してください。

描画・経路探索の改善内容と計測手順は [性能と現在地判定の修正](venue-walk-performance.md) を参照してください。
Androidの初回表示で約30秒かかる問題の原因と修正結果は [Android性能調査・修正](android-performance-investigation.md) に記録しています。

## 起動と確認

アプリ通常のFirebase設定または開発用スタブを準備し、リポジトリルートで `fvm install` と `fvm flutter pub get` を実行します。`apps/app` からアプリ本体を起動します。

```sh
fvm flutter run --release -d web-server --web-hostname=127.0.0.1 --web-port=8774 --dart-define=FLAVOR=dev
```

`http://127.0.0.1:8774/#/venue-map` を開いて3Dに切り替えます。テーマと言語はアプリの設定から変更します。別のプレビュー用エントリーポイントや専用サーバーは使用しません。

```sh
fvm dart analyze
fvm flutter test
node --test tool/venue_map/label-layout.test.cjs
fvm flutter build web --release --dart-define=FLAVOR=dev
```

床画像のGPU読み込み・メモリー上限・mipmapのテストには、ImpellerとFlutter GPUを有効にします。

```sh
fvm flutter test --no-pub --enable-impeller --enable-flutter-gpu test/venue_floor_texture_test.dart
```

Androidではアプリを起動し直し、まだ3Dを開いていない2Dマップから次のチェックを実行できます。
`adb`がPATHにない場合は`--adb`で指定します。20秒以内に3Dの準備完了を確認できなければ終了コード1となり、結果JSONと画面を保存します。
計測にはUI取得の待ち時間を含みます。2D／3Dの往復では既存シーンを再利用するため、初回表示の計測には使いません。

```sh
python3 tool/venue_map/check_android_3d.py --serial emulator-5554 \
  --budget 20 --output /tmp/venue-map-startup
```

## 看板画像の更新

3D用の看板・装飾は`assets/venue_map/walk_artwork/`の生成済みPNGを使います。起動時には文字の描画を行いません。会場名・スポンサー名・翻訳・フォント・看板の寸法や描画を変更したら、`apps/app`で次を実行し、PNGと`manifest.json`をコミットします。

```sh
fvm flutter test tool/venue_map/generate_walk_artwork.dart
fvm flutter test test/venue_walk_artwork_test.dart
```

生成にはリポジトリ指定のFlutterと同梱のNoto Sans JPを使います。既存の描画レシピは`venue_artwork_painter.dart`、会場寸法との対応は`generate_walk_artwork.dart`にあります。立体の看板寸法を変更する場合は、生成側の寸法も合わせてください。整合性テストで入力の変更と同梱漏れを検出します。

床は最初に選択中のテーマだけを読み込みます。別テーマへの初回切り替えでは、新しい床画像の準備ができるまで現在の会場の色を保ち、床・壁・机をまとめて切り替えます。2回目以降は読み込み済みの画像を再利用します。

## 操作

| 操作                         | 動作                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| スティック / WASD / 矢印キー | 表示中のカメラを基準に移動。だしゅまるの向きには左右されない |
| 右下の走るアイコン / Shift   | 押している間だけ走る。離す・キャンセル・非表示で解除         |
| 床をタップ                   | 壁や机を避けて指定地点へ歩く                                 |
| 場所を探す                   | ホールや設備、スポンサーの近くへ歩く                         |
| ドラッグ                     | カメラを回転                                                 |
| ピンチ / ホイール            | 拡大・縮小                                                   |
| 地図アイコン                 | 全体表示。移動を止め、ホール名を重ねて表示                   |
| 手をふる                     | カメラを向いて手をふる                                       |
| 入口に戻る                   | 開始位置へ戻る                                               |
| Esc / 停止アイコン           | 自動移動を停止                                               |

スマートフォンではだしゅまるを近くから追い、前方の景色が見える構図にします。3Dから2Dへ切り替えて戻っても、歩いていた位置とカメラを保ちます。別タブ、検索シート、遊び方を開いている間やアプリがバックグラウンドにある間は、移動と連続描画を停止します。

2Dと共通の `floor_plan.json` から歩ける範囲を作ります。スポンサーの検索結果は机の中心ではなく、到達できる周囲の地点へ案内します。端末の実際の位置情報は使いません。読み込みに失敗・タイムアウトした場合は再試行または2Dへの復帰を選べます。

## 会場と撮影

4ホール、22社の看板、ステージ、ホールの出入口、エスカレーター、クリエイティブボードを配置します。スポンサー名の全行で文字サイズと太さをそろえ、短い社名だけを拡大しません。看板からBOOTH表記や補足コピーを外し、正式名は検索にも残します。

クリエイティブボードは提供された写真を参考に、黒い3枚のパネル、白いFlutterKaigiロゴと左手前の台座を表現しています。配置と歩行判定は同じデータを使い、スポンサー区画と重ならないようにしています。

エスカレーターは金属の踏段、黄色い段鼻、黒い手すり、ガラス側板を表現します。[施設のフロア構成](https://www.hmc.conventionhall.jp/facility/img/floorguide.gif)と[入口の写真](https://www.hmc.conventionhall.jp/facility/img/photo01.jpg)を参考に、西側は6F、東側は4Fへ続く形とし、下階側に床の開口を設けます。運転方向や実測した階高を示すものではありません。

ライト・ダークともアプリのテーマを使い、操作パネル、文字、撮影フレーム、床・壁・机の色を切り替えます。スポンサー看板は文字を読みやすい配色に保ちます。

操作説明・移動案内・撮影画面・3D看板は、アプリの日本語／英語設定に追従します。言語の変更では散歩の位置・経路やカメラを維持し、看板の文字テクスチャだけを差し替えます。

カメラのアイコンから現在地で撮影、隣の写真アイコンからクリエイティブボード前への移動ができます。立つ・手をふる・座る・ジャンプのポーズ、フレーム、カメラの向きを選んでPNGプレビューを作成します。Webは通常のブラウザダウンロードで保存します。閉じると撮影前のカメラに戻ります。

iPhone・Android実機のFPS、発熱、長時間のメモリー使用は未計測です。ネイティブの写真保存は未実装で、プレビューまでが対象です。
