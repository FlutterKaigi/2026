# だしゅまると、会場さんぽ

会場マップの「さんぽ」から、だしゅまるを操作する Flutter Scene の画面を開けます。既存の `floor_plan.json` と床画像を使い、同じ会場内を歩きます。SDK は Flutter **3.47.0 / Dart 3.13.0**、`flutter_scene` は **0.23.0** に固定しました。

技術選定・旧 SDK との互換性・モデルの構造は [調査レポート](flutter-scene-research.md)、出典と権利の情報は [モデルの README](../../assets/models/README.md) に記録しています。

## 起動

リポジトリルートで `fvm install`、`fvm flutter pub get` を実行後、`apps/app` から起動します。プレビューは Firebase の初期化を必要としません。

```sh
fvm flutter run --no-pub -d web-server -t tool/venue_map/walk_preview.dart --web-port 8774
```

今回の操作確認には release ビルドと専用のローカルサーバーを使いました。in-app browser で記念写真を保存するときも、この起動方法を使います。

```sh
fvm flutter build web --release --no-pub --no-wasm-dry-run --dart-define=VENUE_WALK_PHOTO_ENDPOINT=/__demo/photos -t tool/venue_map/walk_preview.dart --output=build/venue-walk-demo
python3 tool/venue_map/serve_walk_demo.py --port 8774
```

`http://127.0.0.1:8774/` を in-app browser で開きます。本体の会場マップからの遷移は、従来の `tool/venue_map/preview.dart` でも確認できます。

## 操作

| 操作                               | 動作                                                             |
| ---------------------------------- | ---------------------------------------------------------------- |
| WASD / 矢印キー / 画面内スティック | 画面に映っているカメラを基準に移動。モデルの向きに左右されない   |
| 右下の走るアイコン                 | 押している間だけ走行。離すと歩行に戻る。スティックと同時操作可能 |
| Shift                              | 押している間だけ走行                                             |
| 床のクリック・タップ               | 壁・ブースを避けて指定地点まで移動                               |
| ホール名                           | 入口を通ってホールの中央へ移動                                   |
| Esc / 停止ボタン                   | 自動移動を停止                                                   |
| ドラッグ                           | 視点の回転                                                       |
| ホイール / ピンチ                  | 拡大・縮小                                                       |
| 全体を見る / 追いかける            | 会場全体と追従カメラの切り替え                                   |
| 手をふる                           | カメラを向いて Wave を再生                                       |
| 入口に戻る                         | ホワイエの開始位置に戻す                                         |

縦長画面の全体表示は会場を90度回して収め、ホール名を重ねて表示します。全体表示へ切り替えると歩行を停止し、移動・撮影ボタンを畳みます。「さんぽに戻る」、または行き先の選択で追従表示に戻れます。訪問したホールを記録し、大画面の一覧とスマホの行き先シートに訪問状況を表示します。自動移動の完了時には到着メッセージを4秒間表示します。移動できない地点を選んだときは、それまでの自動移動を止めて知らせます。位置はデモの操作で変わり、端末の実際の現在地は取得しません。

幅600px未満、または高さ500px未満の横画面では、だしゅまるを近くから追う散歩用の構図になります。追従距離を通常の半分にしてカメラを低くし、だしゅまるを中央より少し下に置いて前方の景色を見せます。構図の基準はカメラの向きなので、モデルが振り向いてもスティックの方向は変わりません。ズーム・回転は引き続き操作でき、全体表示と記念撮影はそれぞれの構図を使います。

スマホではミニマップと常設のホール一覧を畳み、右上の地図アイコンから全体表示、その下の道しるべアイコンから行き先を開きます。行き先を選ぶと追従カメラで歩き始めます。撮影・手をふる・走る操作は画面の端に残しています。短い横画面では、上部の案内・撮影操作と下部の移動操作を横並びにし、ミニマップやホール一覧との重なりを避けます。遊び方の説明はスクロールできます。

この調整は360×780・390×844とPC幅1280pxで表示を確認しました。行き先の選択とMaterialへの到着、全体表示・撮影から散歩への復帰をin-app browserで確認し、コンソールのエラー・警告はありません。移動方向・走行操作の9件、全体の静的解析、release Webビルドも成功しています。

走るボタンは押した瞬間から有効になり、離すと歩く速度に戻ります。ボタンの外へ指がずれても、離すまでは走行を維持します。指を離した場合・タッチがキャンセルされた場合・画面がバックグラウンドへ移った場合は解除します。スティックも入力状態とつまみの表示を同期し、停止・リセット後は同じ指を動かしても再開せず、新しいタッチから操作を受け付けます。

## 会場の装飾と撮影のサンプル

`walk_preview.dart` は `VenueWalkPage(showcase: true)` を開きます。4ホールの看板とステージ、22ブースの社名パネルと天板、クリエイティブボードを追加しています。看板の文字は既存の会場データから生成します。ホール看板・出入口・トイレのサインも表示面と同じ縦横比で生成し、文字の引き伸ばしを防ぎます。ホール看板はイベント名とホール名に整理し、仮の番号や英語コピーは外しています。設営の実寸を示すものではなく、コンテンツの雰囲気を試すサンプルです。実体のある装飾は歩行経路の障害物にも追加しています。

スポンサー看板からイベント名とBOOTH表記を外し、社名を中心に描画しています。看板の表示面と同じ縦横比でテクスチャを生成し、文字の引き伸ばしを防ぎます。看板の大小にかかわらず、3D空間上の文字サイズ・太さ・行間を統一し、短い社名だけを拡大しません。ブランド名は1行を維持し、「株式会社」「(株)」や末尾の括弧内の補足を別行に分け、すべての行を同じ文字サイズ・太さで描画します。幅または高さが収まらない場合は、看板内の全行を共通の倍率で縮めます。例えば「ゆめみ」と「（アクセンチュア）」、「株式会社」と「サイバーエージェント」のように、語の途中で折り返しません。すべての文字を残し、元のスポンサー名・ブース配置は変更しません。

クリエイティブボードは提供された写真を参考に、黒い3枚のパネル、小さな白いFlutterKaigiロゴ、左手前の黒い台座を再現しています。マークの輪郭はリポジトリの `apps/website/web/images/logo.svg` にある白いロゴを使用し、文字はNoto Sans JPで描画しています。

入口側の4本のエスカレーターには、溝のある金属ステップ、黄色い段鼻、丸く折り返す黒い手すり、透けるガラス側板、金属の乗り場を追加しています。配置・幅・中央を向く乗り場は既存の `escalators` データから求め、部品を歩行不可の範囲内に収めています。

立体モデルと重複する、床画像上の平面エスカレーター（踏段線・輪郭・西端の斜め部分）はデモでは描画しません。該当部分を床画像のメッシュから切り分け、同じホワイエ色の無地の床に置き換えています。下り側の開口をふさがず、乗降床を残します。既存の2Dマップ用画像と歩行判定はそのまま使います。

床の置き換えによる開口の保持・面積・非重複と、西端の斜め部分の除去を2件追加して確認しました。エスカレーターと歩行経路の14件、静的解析、release Webビルドが成功しています。入口への移動と低い視点からの表示をin-app browserで確認し、元の踏段線や輪郭の重複はなく、描画エラー・警告もありませんでした。

[公式のエントランス写真](https://www.hmc.conventionhall.jp/facility/img/photo01.jpg)の6F案内と[フロア構成図](https://www.hmc.conventionhall.jp/facility/img/floorguide.gif)の4F–5F・5F–6F接続を参照し、西側2本を6Fへ上がる形、東側2本を4Fへ下がる形にしています。上下階への接続と、各ベルトの運転方向は別です。実際の運転方向は固定していません。下階へ続く部分では床画像と床板の両方に開口を設け、中央の乗降床を残しています。床画像のUV座標を維持するため、周囲の壁・ブースとの位置合わせは変わりません。高低差は模型用の表現で、実測した階高ではありません。他の階への移動やステップの運転アニメーションは含みません。

上下階への傾斜、乗降床の保持、床画像と床板の開口面積・非重複、中央乗り場から各ホールへの到達を6件で検証しています。既存の移動・装飾・操作を含む25件が成功し、全体の静的解析とrelease Webビルドも成功しました。in-app browserでは床画像の位置合わせ、上下階へ続く形状、入口・ホールへの移動を確認し、描画エラー・警告はありませんでした。

10か所のホール出入口には金属枠、開いた木製扉、敷居とホール名のサインを追加しました。主入口には壁の位置に合わせた支柱、頭上の案内サイン、マットを置き、トイレにも案内板を加えています。主入口の看板と支柱は、近いカメラとだしゅまるの間にある場合に滑らかに非表示にして視界を確保します。離れた視点や全体表示では元の姿を描画し、床のマットは残します。繰り返すステップや枠は同じ形状・材質をまとめて描画し、追加のモデルファイルやパッケージには依存しません。

設置場所は図面の `creative_board` 区画（x:808–918、y:380–402）から算出し、台座とボードを区画内に収めています。前回の固定座標ではボードの右端が958.625となり、区画からはみ出すことをテストで再現しました。図面と描画の座標不一致を直接確認できたため、他の原因の探索は省略し、配置データを描画・衝突判定で共有しました。周囲の植物・バナーと大きな床サインは撤去しています。

配置の回帰テスト4件で、区画内への収まり、全22スポンサーブースとの非交差、東西の通路と各ブース前への到達、撮影地点から4ホールへの移動を確認しています。既存の移動・方向・2本指の操作を含む19件が成功しました。

アプリ本体から開く `VenueWalkPage()` は従来の表示です。今回の装飾・撮影UIはデモで有効になり、移動方向の修正は両方に適用されます。新しいパッケージ依存は追加していません。

| デモの操作                        | 動作                                                                   |
| --------------------------------- | ---------------------------------------------------------------------- |
| 左上の写真スポットのアイコン      | クリエイティブボード前の撮影地点へ自動で歩く                           |
| 左上のカメラ                      | 現在いる場所で撮影モードを開く                                         |
| 立つ / 手をふる / 座る / ジャンプ | ポーズを選択。手をふるはループし、座る・ジャンプは撮影向きの姿勢で保持 |
| ドラッグ / ピンチ / ホイール      | 撮影アングル・距離を調整                                               |
| 顔のアイコン                      | 現在のカメラにモデルを向ける                                           |
| 右上の四角いアイコン              | イベント名入りフレームの表示切り替え                                   |
| 左下の目のアイコン                | 録画用にUIを隠す。画面のタップで戻る                                   |
| シャッター → PNGを保存            | 操作UIを含めない記念写真を生成し、WebでPNGを保存                       |
| 左上の閉じる / Esc                | 撮影前の視点に戻って、さんぽを再開                                     |

写真は `RepaintBoundary` で表示領域の2倍の解像度に書き出します。短い横画面ではポーズとシャッターを右側にまとめ、写真の高さを確保します。ポーズ選択時は重みを即座に切り替え、直後に撮影しても途中のブレンド姿勢にならないようにしています。ネイティブでは写真プレビューまでが対象で、ファイル保存ボタンはWebのみです。動画ファイルの書き出しは含まず、UIを隠した状態で端末の画面録画を使います。

今回の in-app browser では Blob / data URL のダウンロードイベントを確認できず、同じPNGのHTTPリンクでは成功しました。専用サーバーは生成したPNGをメモリーに最大8枚保持し、HTTPの添付ファイルとして返します。1枚8MiBまで、127.0.0.1のみで待ち受け、終了時に画像を破棄します。通常のWebビルドでは、このオプションを付けずにブラウザー内のBlob URLを使います。

実画面で、4種類のポーズ、PNGプレビューとダウンロード、フレーム切り替え、UI非表示とタップでの復帰を確認しました。専用サーバーも、画像の往復、画像形式・リクエストヘッダー・Origin・サイズの検査、保持上限の計6点を確認しています。

## スティックの方向ずれの修正

カメラを90度回すと右入力が画面左に投影されることを、実際の `PerspectiveCamera.worldToScreen` と移動処理で再現しました。従来の回転変換には符号の不一致があり、目標のカメラ角度を使っていたため、全体表示への補間中にも表示と入力がずれました。

移動量は、実際に描画している `camera.forward` の水平成分と右方向から求めるよう変更しました。モデルの姿勢を参照せず、カメラの回転・補間・縦長の全体表示でも画面上の方向と揃えます。また、手を振るときの向きも実際のモデル位置とカメラ位置から計算します。

`test/venue_walk_direction_test.dart` の7件は、5方向のカメラ、視点補間中の入力、90度回転後のモデルの正面を検証します。修正前は方向の6件中4件が失敗し、回転の符号だけを直しても補間中の1件が失敗しました。最終修正で方向・正面の全7件が成功しました。

## 実装

- `lib/feature/venue_map/data/venue_walk_scene.dart`: Scene、モデル、カメラ、入力の移動量、アニメーションのブレンドを管理。移動用の親 Node とモデル内の骨格を分離し、`SceneView.onTick` で `Scene.update(dt)` を一度だけ呼びます。
- `lib/feature/venue_map/data/venue_walk_navigation.dart`: 共通座標の歩行可能判定、壁沿いの移動、A* と経路の平滑化。壁117本、一般利用外の領域、ブース、エスカレーターを避けます。半径7px、グリッド6pxで、斜め移動・経路短縮も同じ衝突判定を通します。
- `lib/feature/venue_map/ui/page/venue_walk_page.dart`: キーボード、スティック、床のタップ、ミニマップ、ホールへの移動、狭い画面への対応。専用のライトテーマを使用します。
- `lib/feature/venue_map/data/venue_walk_decorations.dart`: サンプルの立体看板・ステージ・クリエイティブボードと、Canvasによる文字テクスチャの生成。
- `lib/feature/venue_map/data/venue_walk_architecture.dart`: サンプルのエスカレーター、出入口、設備サイン。共通の区画データを基準に配置し、金属・ゴム・ガラス・木材を描き分ける。
- `lib/feature/venue_map/data/venue_escalator_layout.dart`: 上下階への接続、段の高さ、下階へ続く開口と床の分割。描画と配置のテストで共有。
- `lib/feature/venue_map/data/venue_creative_board_layout.dart`: 図面の区画を基準にしたボード・台座の配置と撮影地点。描画と歩行の衝突判定で共有。
- `lib/feature/venue_map/ui/widget/venue_walk_photo_studio.dart`: ポーズ、フレーム、UI非表示、PNGプレビュー。
- `lib/feature/venue_map/data/venue_walk_photo_save*.dart`: Webの保存処理とネイティブ向けの分岐。
- `tool/venue_map/serve_walk_demo.py`: in-app browser 用のローカルプレビューとPNGの一時配信。Python標準ライブラリーのみ使用。
- `hook/build.dart`: GLB と床 PNG を Flutter Scene の形式にビルド時変換。`loadScene` / `loadTexture` は元のパスで参照し、`ResourceGroup` で読み込みと解放を対応させます。

Web は Flutter Scene の WebGL2 バックエンドを使います。iOS と Android には Flutter GPU の有効化設定を追加しています。フォーカス喪失時は移動入力を解除し、バックグラウンドでは tick を停止します。復帰直後も `dt <= 0.05` で大きな位置の飛びを防ぎます。

### 残る確認

iOS シミュレータービルドは Firebase の Swift Package 解決で停止しました。今回のログでは `firebase_auth 6.5.6` が SDK `12.15.0`、`firebase_core 4.13.0` が `12.17.0` を要求しています。9月9日の既存会場マップの検証にも同じ SDK 版同士の衝突が記録されており、Flutter 更新以前からある問題です。今回 Firebase 全体の更新は行っていません。

iOS / Android の実機描画・性能、Wasm ビルドは未確認です。今回の歩行画面は日本語で、20.8万三角形のモデルを1体描画する操作デモです。一般公開の前には端末性能の測定とモデルの利用条件確認が必要です。
