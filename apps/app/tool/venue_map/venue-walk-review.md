# 会場さんぽデモの見直し

2026-09-14。対象は `walk_preview.dart` から開く会場さんぽデモ。スマホでの散歩・会場の見え方・移動操作・案内・撮影を、実画面と関連コードで見直した。

## 見つかった点と対応

| 箇所                       | 気になった点                                                                         | 対応                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 初期カメラ                 | 入口の横看板が手前に大きく写り、会場の景色を遮る                                     | 近いカメラとだしゅまるの間にある入口の看板・支柱を滑らかに非表示にする。遠景と全体表示では表示し、床のマットは残す |
| スマホ横画面               | 撮影ボタンとスティック、ミニマップとリセットが重なる                                 | 高さ500px未満の横画面を専用配置にする。上部の案内・撮影、下部の移動操作を横並びにし、だしゅまるを近くから追う      |
| 小さい画面の見出し         | 320px幅で「ぽ。」だけが次の行になる                                                  | 見出しを一行に保ち、幅に合わせて全体を縮める                                                                       |
| 全体表示                   | 立体の看板を上から読むのが難しく、ボタンもホール名に重なる                           | ホール名を画面に重ねて表示。移動・撮影操作を畳み、戻るボタンを表示。全体表示に入ると歩行を停止する                 |
| 行き先選択                 | 画面サイズや選び方によって、全体表示のまま自動移動する                               | 有効な目的地を選ぶと追従カメラで歩く動作に統一                                                                     |
| 移動の完了                 | 到着すると移動中の表示が消えるだけ                                                   | 目的地への到着を4秒間表示。スマホの行き先一覧にも訪問数と訪問済みの表示を追加                                      |
| 移動できない地点           | 新しい目的地に行けなくても、直前の自動移動を継続する                                 | 直前の経路を解除してから新しい経路を求め、行けないときは停止して知らせる                                           |
| スティック                 | リセットで入力を止めても、押したままのつまみが戻らない                               | 入力値と表示を同期。解除後の同じ指の移動を無視し、新しいタッチから再開する                                         |
| ホール・入口・トイレの看板 | 固定比率の画像を異なる比率の板に貼り、文字が変形する                                 | 表示面に合わせた比率で文字画像を生成。幅の異なる入口は別の画像として保持する                                       |
| ホール看板の情報           | 仮のホール番号と「MEET. TALK. ASSEMBLE.」が場所の理解に役立たない                    | イベント名とホール名に整理。入口の補助表記は「入口」にする                                                         |
| 横画面の撮影               | 下部の操作で写真の高さが減り、だしゅまるが小さい                                     | ポーズ・シャッターを右側へ移動。写真プレビューも画面の高さに収める                                                 |
| ポーズを選んだ直後の撮影   | 前のポーズとのブレンド途中を撮る可能性がある                                         | 撮影モードでは選んだポーズへ即座に切り替える                                                                       |
| 遊び方                     | 技術説明が中心で、横画面では説明の下部が見えない                                     | 歩く・押して走る・見回す・自動移動・撮影の説明を先に置き、スクロールできるようにする                               |
| 読み込み・描画の後始末     | 初期読み込み中に閉じると、終了後にも共有リソースを取得しうる。文字描画の後始末も不足 | 非同期読み込みの境目で終了状態を確認し、描画に使ったTextPainterを解放する                                          |

スポンサー看板については、22社の元の名前・ブース位置、同じ文字サイズと太さによる改行、名前全体を同率で縮める処理を維持した。クリエイティブボードの配置、上下階へ続くエスカレーター、床の開口も維持している。

## 残る改善余地と確認範囲

1. **到着後の体験**：ホールやブースは、看板を見る・写真を撮る体験が中心。次に充実させるなら、各ホールで違うリアクションや、訪問記録を使った小さなスタンプラリーが候補。実際の開催内容を決め打ちする展示は追加していない。
2. **長いスポンサー名の遠景での読みやすさ**：改行と縮小を揃えても、離れた看板の文字数には限界がある。今後は近づいたブースの名前を表示する補助UIなど、看板を大きくせずに読める方法を検討できる。
3. **実機性能**：画面サイズの確認はブラウザ上。iPhone・Android実機のFPS、発熱、長時間のメモリー使用は未計測。ネイティブの写真保存は従来どおり対象外で、プレビューまで。

## 表記の調整

イベント名はヘッダー・会場の看板・写真フレームを含めて `FlutterKaigi` に統一した。「ホワイエ」の場所名を表示せず、場所名も移動案内もないときはカード全体を隠す。移動中・到着時の案内と、ホール名・エントランスの表示は維持する。
