# 会場さんぽの見直し

対象はアプリ本体の会場マップ内に表示する3Dの散歩機能です。

| 箇所               | 対応                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| 画面構成           | 3D切り替えでマップ領域に散歩UIを表示。下タブ・検索・2D切り替えを維持                |
| テーマ             | 操作パネル・文字・撮影フレームはアプリのColorSchemeを使用。床・壁・机も両テーマ対応 |
| スマートフォン     | だしゅまるを近くから追う構図。縦画面と短い横画面で操作配置を変更                    |
| 移動方向           | 表示中のカメラを基準に計算し、モデルの向きと分離                                    |
| 走行               | アイコンを押している間だけ走る。指を離す・キャンセル・非表示で解除                  |
| 入口の視界         | カメラとだしゅまるの間の看板・支柱を滑らかに隠す                                    |
| 全体表示           | 歩行を停止して移動・撮影操作を畳み、ホール名を画面に重ねる                          |
| 検索               | 既存の場所検索から自動移動。スポンサーは到達可能なブース周囲に案内                  |
| カメラの保持       | 2Dと3Dを往復しても歩行位置と視点を保持                                              |
| 非表示の処理       | 別タブ・検索・遊び方・バックグラウンドでは移動と連続描画を停止                      |
| スポンサー看板     | 全行を同じ文字サイズ・太さに統一。BOOTH・補足コピーを除去                           |
| オブジェクトの配置 | ボードを区画内に収め、スポンサーと通路を避ける                                      |
| エスカレーター     | 上下階への接続を表現し、重複する床面の踏段表現を除去                                |
| 撮影               | 選んだポーズを即時適用。PNGは通常のブラウザ保存を使用                               |
| 読み込み失敗       | 30秒でタイムアウトし、再試行・2D復帰を表示。取得済みリソースを解放                  |
| 開発時の確認       | 別のプレビュー画面や専用サーバーを使わずアプリ本体で確認                            |

イベント名は `FlutterKaigi` に統一しています。参加者向けに不要な場所名は表示せず、ホール名・エントランス・移動案内を表示します。

## 検証範囲

テストではカメラに対する移動方向、2本指の走行、停止・キャンセル、各ホールと全22ブース前への到達、ボードとスポンサーの非交差、床の開口、入口の視界を確認します。画面テストでは3Dが同じマップ内に収まること、ダークテーマの継承、下部ナビゲーションと2D復帰を確認します。

ブラウザでは通常のアプリをスマートフォンサイズで起動し、テーマ切り替え、2D/3D切り替え、検索からの移動、撮影からの復帰を確認します。実機性能の計測とネイティブの写真保存は今後の対象です。
