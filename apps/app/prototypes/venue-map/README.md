# 会場マップ HTML 画面案

Flutterアプリへ反映する前の検討用プロトタイプです。`venue-map.html` をブラウザで開くだけで動作します。GPT Imageで生成した地図、名称・タップ領域、3Dの描画コード、ロゴ、提供された参考図はHTML内に含めています。

ローカルで表示する場合:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory apps/app/prototypes/venue-map
```

[プレビュー](http://127.0.0.1:8765/venue-map.html) / [スマートフォン幅のプレビュー](http://127.0.0.1:8765/venue-map.html?device=phone)

## 画面案の仕様

- 初回は2D平面図を表示し、場所の選択・拡大・ドラッグで移動できます。
- GPT Imageで整理した詳細図を下地に使い、名称はHTMLで重ねます。文字は拡大率に影響されず、回転時も水平のまま表示します。
- 2D／3Dの選択を端末内に保存し、再読み込みでも最後の表示方法を復元します。保存対象は表示方法のみです。
- ホールや設備を地図・一覧・検索結果から選ぶと、その場所を強調し、場所名と施設の表記を表示します。ホール名と設備は常に表示し、隠すための設定は設けません。
- 場所を選んだときだけ、その場所と周囲の通路が分かる程度に寄せて拡大します。2D・3Dとも同じ操作で、追加の中心表示ボタンは設けません。
- 3Dも通常の移動と拡大を一度行うだけです。その後の地図操作には選択状態を使わず、選択地点への固定や追従、以前の回転軸を保持する特別な処理は行いません。
- 一覧の開閉、絞り込み、選択解除、2D／3Dの往復では選択地点へ寄せ直しません。各表示で動かした位置・拡大率を保ちます。
- 「フロア全体を表示」は表示範囲を見失った際に使えます。選択を保ったままフロア全体へ戻します。
- 2D／3Dそれぞれの表示位置・拡大率は、同じページ内で切り替えても維持します。再読み込みではフロア全体に戻ります。2Dで画面の縦横が変わった場合は、新しい向きに全体を合わせます。
- スマートフォンでは地図を縦向きにして広く表示します。回転ボタンで図面と同じ向きにも戻せます。
- 検索欄は下部の「場所を探す」から展開します。初期状態は68pxです。
- スマートフォンでは、選択時に検索ボタンの上へ場所名・施設の表記・閉じるボタンだけを表示します。「場所を探す」は選択前後で同じ位置に残します。全体で約128px、長い名称の場合は自然に高さが広がります。
- 一覧を閉じても場所の選択を保ちます。選択の解除は場所名の右の×から行えます。
- PCでは選択情報を左の一覧の下に表示します。地図の上に詳細カードは重ねません。
- 「中心に表示」「詳細を見る」「場所を変更」「近くの場所」の追加ボタンは設けません。場所を選べば地図が寄り、名称・位置関係と、共通の検索・一覧から場所を確認できます。
- 選択情報には内部スクロールを使いません。検索と選択解除のタップ領域は44px以上です。
- 3Dは既存HTMLのThree.js r160・OrbitControlsのみを再利用し、区画を共通の座標データから描画します。旧シーンの部屋配置は使いません。2D表示中は描画を停止します。
- 初回状態と再起動は、HTML上部の「設計メモ」「再起動を試す」から確認できます。

名称・配置は今回提供された5階配置図を基にしています。参考図はHTMLの設計メモに埋め込んであります。

- [浜松町コンベンションホール 施設案内](https://www.hmc.conventionhall.jp/facility/)
- 既存アセット: `apps/app/assets/html/venue_floor_plan_webview.html`
- アプリの配色: `apps/app/lib/core/designsystem/theme/color_scheme.dart`
- 既存の会場名データ: `packages/data/firebase/seed/firestore/default.json`

地図は検討用の簡略図です。生成画像は外壁の四隅を基準に元図へ位置合わせしています。ホールと通路の大きな位置関係を照合していますが、建築細部やブースの個数・寸法を確定するための図面ではありません。測位、経路案内、セッションとの連携は含みません。アプリのナビゲーションは周辺UIのイメージで、このHTMLでは会場マップのみ操作できます。

HTMLの保存キーは `flutterkaigi-2026.venue-map-prototype.view.v1` です。Flutterへの反映時は既存の `SharedPreferences` に表示方法を保存する想定です。

## 編集・再生成

```sh
python3 apps/app/prototypes/venue-map/build.py
```

- `src/floor-map-gpt-image.png`: built-in image_genで生成した下地画像。
- `src/image-prompt.md`: 使用した最終プロンプトと生成方法。
- `src/reference-plan.png`: 提供された詳細図。座標系は871 × 449。
- `src/floor-plan.js`: 2Dの操作領域と3Dの部屋形状が共有する座標・名称。
- `src/prototype.js` / `src/venue-map.template.html`: 画面、表示設定、2D操作。
- `src/scene3d.js`: 3Dの描画と選択・カメラ操作。

## 検証

- JavaScriptの構文と、ローカルHTTPでの配信を確認。
- ブラウザで320 × 844、424 × 885、1280 × 900の画面を確認。スマホの全体表示で名称が重ならず、ページの横方向へのはみ出しがないことを確認。
- SVG座標とHTMLラベル中心のずれをDOMで測定。修正前の約20〜40pxに対し、修正後は表示中の全11ラベルが0px。
- 検索パネルの展開、名称検索、場所選択、拡大操作、2D／3Dの選択引き継ぎ、再読み込み時の表示方法復元を確認。
- 3Dのホール名・区画・ラベルをPCとスマホ幅で目視確認。
- 2Dでは場所の選択時に移動・拡大することを確認。選択後に地図を移動し、3Dと往復しても移動後の変換値が変わらず、選択地点に寄せ直さないことを確認。
- 3Dでは選択地点が表示中心へ移ることを確認。一覧の開閉と2Dとの往復では、地図の中心に対する4ホールの投影位置の差は0px。選択を保った全体表示も確認。
- 操作を整理した画面を320 × 668のスマホ幅と1280 × 900のPC幅で確認。選択情報の内部スクロールとページの横はみ出しがなく、PCの選択情報が地図を覆わないことを確認。
- 共通の「場所を探す」から検索・選択・絞り込み・一覧を閉じる操作を確認。検索ボタンの縦位置は選択前後で同じ。JavaScriptの構文チェックも通過。

Flutterアプリ本体と実機への反映・検証は、このHTML案を確定した後の工程です。
