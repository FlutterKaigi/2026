# dashboard

FlutterKaigi 2026 管理ダッシュボード（Flutter Web）。

## セットアップ

stg / prod に接続するには `flutterfire configure` で設定ファイルを生成する必要がある（gitignore されているため各自実行が必要）。

```bash
cd apps/dashboard
flutterfire configure
```

dev 環境はエミュレータに接続するため設定ファイル不要。`fvm dart run melos dashboard:run:dev` でそのまま起動できる。

応援LTのコード発行・参加登録には Functions エミュレータも必要。モノレポルートで
`fvm dart run melos functions:install` を初回実行し、
`fvm dart run melos firebase:start:functions` で起動してからダッシュボードとアプリを起動する。

## 環境

| FLAVOR | 接続先 |
| --- | --- |
| `dev` | Firebase エミュレータ（ローカル） |
| `stg` | Firebase Staging プロジェクト |
| `prod` | Firebase Production プロジェクト |

`FLAVOR` はダッシュボードのログイン先と、イベント画面の初期選択環境を決める。
応援LT・クイズの操作対象は、起動後に画面上の「操作環境」で STG / 本番を切り替えられる。

## イベントの操作環境

- 応援LT・クイズの上部にある「操作環境」で STG / 本番を選ぶ。同じログインを使い、
  環境ごとの Google 再認証や、操作先プロジェクトへの管理者アカウント登録は不要。
- 登録コード、参加者、クイズ問題、出題・採点・順位、スポンサー選択肢はすべて選択先のデータ。
  通常の編集・進行操作は選択先へ直接反映される。STG から本番へコピーする場合は、
  クイズの進行コンソールにある「本番へ反映」を使う。
- 本番を選択中は画面上部に「本番のイベントを操作中」を表示する。
- 環境を切り替えると一覧に戻る。前の環境の読み込み・フォーム状態は破棄されるため、
  未保存の編集は切替前に保存する。
- `?environment=stg` / `?environment=prod` をURLに保持する。詳細・問題編集・投影画面・
  ブラウザ再読み込み・ログイン後の復帰でも同じ操作先になる。
- 表示中の画面は2秒間隔で自動更新し、操作後にも再取得する。通信エラー時はエラーを表示し、
  次回の自動更新または「再読み込み」で取得し直す。
- dev ではローカルのみを選択できる。Functions エミュレータも必要。

実体はダッシュボードの接続先プロジェクトにある Cloud Functions `eventAdministration`。
既存の本番反映と同様、接続元の管理者権限を確認し、サーバーの IAM 権限で操作先の Firestore
を読み書きする。ダッシュボードとあわせてこの関数をデプロイする必要がある。
STG のダッシュボードから本番を操作する場合は、既存の本番反映と同じ
`roles/datastore.user` のクロスプロジェクト権限を使う。
詳細は [Functions の設定](../../functions/README.md#eventadministration) を参照。

### STG で確認したクイズを本番へ反映する

1. STG で対象イベントを開き、「本番へ反映」でタイトル・問題一覧・定員を確認する。
2. 「本番に下書きを作成」を押すと、そのイベントだけを別 ID の本番イベントとして作成する。
   コピーするのは設定・問題・非公開の正解と解説。STG の動作確認に使った参加者・回答・得点・
   受付コード・進行状態は持ち込まない。スポンサーは先に本番へ反映しておく。
3. 自動で本番の進行コンソールへ移る。内容を確認して受付コードを発行し、「公開する」を押す。
   本番への反映だけでは参加者アプリに公開されない。

同じ STG イベントの反映済みコピーがある場合は、その本番イベントを開く。既存の本番内容は
上書きしない。確認後に STG の設定や正解が変わった場合も、再確認するまで反映を拒否する。
通信エラー後は同じ確認画面から再試行でき、重複するイベントは作らない。

対象を間違えた場合は、本番の進行コンソールの「反映を取り消す」を使う。参加受付の準備・開始前の
下書き・公開済みイベントのみ対象。内容と履歴を保管したまま非公開にし、ダッシュボードの通常一覧からも
外す。STG を修正して再反映すると新しい ID で作成され、取り消したイベントは復活しない。
参加受付の開始後、参加者・回答・進行データがある場合は取り消しを拒否してデータを保護する。

## よく使うコマンド

モノレポルートから実行する。

| コマンド | 用途 |
| --- | --- |
| `fvm dart run melos dashboard:run:dev` | Chrome で起動（dev / エミュレータ） |
| `fvm dart run melos dashboard:run:stg` | Chrome で起動（stg） |
| `fvm dart run melos dashboard:run:prod` | Chrome で起動（prod） |
| `fvm dart run melos dashboard:build:dev` | web 向けにビルド（dev） |
| `fvm dart run melos dashboard:build:stg` | web 向けにビルド（stg） |
| `fvm dart run melos dashboard:build:prod` | web 向けにビルド（prod） |
| `fvm dart run melos dashboard:deploy:stg` | ビルド → Firebase Hosting へデプロイ（stg） |
| `fvm dart run melos dashboard:deploy:prod` | ビルド → Firebase Hosting へデプロイ（prod） |

## デプロイ

Firebase Hosting へのデプロイは `dashboard:deploy:stg` / `dashboard:deploy:prod` スクリプトで行う。
内部でビルドと `firebase deploy --only hosting` を順に実行する。

事前に Firebase CLI でログインしていること。

```bash
firebase login
```

## データの本番反映

各画面の「本番環境へ反映」ボタンで、STG のデータを本番環境へワンクリックで完全ミラー
できる（作成・上書きに加えて、STG に存在しない本番側ドキュメントの**削除**も行う）。

| 画面 | 反映されるコレクション |
| --- | --- |
| スポンサー一覧 | `sponsors` |
| ニュース一覧 | `news` |
| セッション一覧 | `venues` / `speakers` / `sessions` / `timelineEvents` |

セッション系の 4 コレクションは相互に参照を持つ（`sessions.venueId` / `sessions.speakerIds` /
`timelineEvents.venueId`）ため、個別ではなく**まとめて**反映する。参照切れを避けるため、
参照される側から作成・上書きし、削除は逆順に実行される。

- 実体は STG プロジェクトの Cloud Functions `syncCollectionsToProd`（[functions/README.md](../../functions/README.md) 参照）
- 実行前に dry run の結果（作成/更新/削除の件数、複数コレクションの場合は内訳）が確認ダイアログに表示される
- ボタンは stg / dev フレーバーでのみ表示（prod では非表示）
- dev フレーバーでは `localhost:5001` の Functions エミュレータに接続する

## 応援LTの参加登録

「応援LT」（`/support-lt`）で共通の6桁の登録コードを発行し、参加人数と参加者一覧を確認する。

- コードに有効期限はなく、再発行するまで有効。発行日時はブラウザのローカル時刻で表示する
- 「コードを再発行」は確認後に現在のコードを無効にする。登録済みの参加者は保持される
- 参加者はアプリのアカウントページにある「応援LT参加登録」からコードを入力する
- 参加人数・表示名・UID・登録日時は2秒間隔で自動更新される
- 管理にはメール確認済みの `@flutterkaigi.jp` アカウントと `admins/{uid}` の管理者登録が必要
- 権限不足・通信失敗時にはエラーを表示し、「再読み込み」で取得し直せる

## スポンサー一覧の操作

スポンサー情報の**原本はスプレッドシート（GAS 連携）**。ダッシュボードで編集できるのは
**ロゴ 2 種（プライマリー/セカンダリー）と slug のみ**で、それ以外は参照用の表示。
新規作成もスプレッドシート側で行うため、作成ボタンは無い。

- ロゴ・slug のセルを**ダブルクリック**するとその場で編集できる（Enter / フォーカス移動で確定、Esc でキャンセル）。編集可能列はヘッダーに ✎ アイコンが付く
- 空文字で確定すると未設定 (null) として保存される
- 閲覧状態でもセルのテキストはドラッグで選択・コピーできる
- 上部のフィルタチップで「ロゴ未設定」「slug未設定」の入力漏れを絞り込める（複数選択は AND、空文字も未設定扱い）
- ヘッダークリックでソート（昇順 → 降順 → 解除）
- 未設定だと Web サイト表示に影響する項目（slug・プライマリーロゴ）は赤色でハイライトされる

## ニュース一覧の操作

News は**このダッシュボードが編集元**（外部の原本は無い）ため、全項目をテーブル上で
編集でき、新規作成も一覧画面から行える。Sponsor と異なり、セルの編集は逐次自動保存
されず、上部の「保存」ボタンで**一括コミット**する。

- 「行を追加」で先頭に空の新規行が追加される（公開日時のみ現在時刻がデフォルト）
- タイトル (ja/en)・URL (ja/en) のセルは**ダブルクリック**でその場編集（Enter / フォーカス移動で確定、Esc でキャンセル）
- 公開日時のセルは**クリック**で日時ピッカーが開く
- 編集内容は保存するまで画面上の下書きにのみ反映される。ページを再読み込みすると未保存の変更は失われる
- 「保存」ボタンで dirty な行（新規行・編集済み行）をまとめて Firestore へ書き込む。必須項目未入力や不正な URL がある行は保存されずセルが赤くハイライトされる（他の正常な行は保存される）
- ヘッダークリックでソート（昇順 → 降順 → 解除）
- 既存行の削除は行ごとの削除アイコン（即時実行、確認ダイアログあり）。新規行は破棄アイコンで一覧から取り消せる（Firestore には未反映のため確認不要）

## クイズ大会

クイズ大会の作成・6桁受付コードの発行・受付人数確認・チーム編成・出題・採点を行う。
進行操作にはCloud Functionsが必要。問題表示と回答開始を分け、読み上げ後にタイマーを開始する。
投影専用画面は `/quiz/:eventId/project`。受付コードや管理操作を映さずに問題・結果を表示できる。

受付再開・参加取消・再編成は初出題前のみ。正解発表前は時間延長できる。
通信エラー時の再試行、早期終了などの詳細は[当日の運用手順](../../docs/quiz-event/RUNBOOK.md)を参照。
